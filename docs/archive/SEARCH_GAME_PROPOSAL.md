# 탐색 실습 게임 구상 (1-1-2)

> 만들자고 정한 건 아직 아닙니다. 어떤 게 수업에 맞는지 고르시라고 정리한 것입니다.

## 왜 게임인가

탐색은 말로 설명하면 "그래서 뭐가 다른데요"가 되는 단원입니다.
학생이 **직접 헤매 보고 나서** 규칙을 주면, 규칙의 값어치를 몸으로 압니다.
물주기 때 쓴 방식 그대로 — **먼저 하게 하고, 끝나고 되짚기**.

탐색 파트는 네 꼭지입니다.

| 차시 | 내용 | 학생이 겪어야 할 것 |
|---|---|---|
| 1-1-2 ①| 문제 해결과 탐색 | 상태·연산자·상태 공간, 탐색 트리가 자란다는 감각 |
| 1-1-2 ②| 맹목적 탐색 | 순서 규칙(깊이 먼저 / 너비 먼저)이 왜 필요한가 |
| 1-1-2 ③| 지능적 탐색 | 힌트(휴리스틱)가 있으면 얼마나 덜 헤매는가 |
| 1-1-2 ④| 탐색으로 문제 해결 | 실제 문제를 상태 공간으로 옮겨 보기 |

## 후보

### A. 미로 보물찾기 — 세 라운드 (추천)

한 게임인데 라운드를 바꿔 가며 **탐색 파트 내내** 씁니다.

| 라운드 | 화면 | 쓰는 차시 | 학생이 느끼는 것 |
|---|---|---|---|
| 1 · 깜깜이 | 한 칸 앞만 보이는 미로. 아무 규칙 없이 돌아다님 | ① | 헤맨 칸이 잔뜩 쌓인다 |
| 2 · 규칙 | 갈림길에서 **깊이 먼저 / 너비 먼저** 중 하나를 골라 진행 | ② | 규칙마다 발자국 모양이 다르다 |
| 3 · 힌트 | 칸마다 "보물까지 대충 몇 칸" 이 보임 | ③ | 훨씬 적게 밟고 도착한다 |

- 점수 = **밟은 칸 수가 적을수록 높게**. 물주기처럼 실명 순위 5등까지.
- 끝나면 되짚기: 방금 밟은 칸을 **탐색 트리**로 다시 그려 주고
  "이게 상태 공간이고, 네가 한 게 탐색이다" 로 연결.
- 라운드 3 뒤에 라운드 1 기록과 나란히 보여 주면 휴리스틱의 값어치가 한 장에 정리됩니다.

**장점** 한 번 만들어 세 차시에 씀 · 개념 세 개(상태 공간·맹목/지능 탐색)를 한 화면에서 이어 줌
**단점** 만들 것이 가장 많음 (라운드 3개 + 트리 되짚기 화면)

### B. 물병 붓기 — 상태 공간 만들기

8L·5L·3L 물병으로 4L 만들기. 한 번 부을 때마다 옆에 **상태 트리가 한 칸씩 자랍니다.**

- 점수 = 목표까지 **몇 수**에 갔나 + 만들어 본 상태 수
- 끝나면 "너는 12개 상태를 봤고, 최단은 6수였다" 를 트리 위에 겹쳐 보여 줌

**장점** ① 차시에 정확히 맞음, 만들기 쉬움 (칸이 3개뿐)
**단점** 맹목/지능 탐색까지는 못 감. 손이 아니라 머리로 하는 활동이라 조용한 편

### C. 따뜻해요 차가워요 — 휴리스틱만

격자에서 보물찾기. 1라운드는 아무 정보 없이, 2라운드는 누를 때마다 "가까워졌다/멀어졌다".

**장점** 가장 만들기 쉬움 (30분짜리)
**단점** ③ 차시 한 번만 씀

## 추천

**A 를 뼈대로 하되, 라운드 1·2 를 먼저 만들어 ①②차시에 쓰고, 라운드 3 은 ③차시 전에 붙입니다.**
한꺼번에 다 만들지 않아도 되고, 앞 라운드를 수업에서 써 본 뒤 뒤 라운드를 고칠 수 있습니다.

### 조심할 것 (이미 대가를 치른 것들)

- **타이머 도는 중에 `render()` 를 다시 부르지 말 것.** 물주기가 이 버그였습니다 —
  값만 갈아끼우는 `_pwPaint()` 같은 함수를 따로 두세요.
- 버튼은 **`data-action`** 이 있어야 눌립니다. 칸마다 `data-r` `data-c` 를 붙이는 방식도 물주기와 같게.
- 카드형 버튼은 `display:block` (전역 `button{display:inline-flex}` 때문).
- 순위 읽기는 **`withTimeout()`** 으로 감쌀 것.
